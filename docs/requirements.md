## 1. 产品概述

本产品是一个本机 Codex 控制台，用于管理多个 Codex CLI 身份档案、统一查看本机任务，并将经脱敏的任务状态推送到飞书、Telegram 和 Discord。

它管理的是用户主动注册的本地档案及其可公开枚举的 Codex 任务；它不是 OpenAI 账号后台，也不接管或修改 Codex 桌面端的登录状态。

### 1.1 目标

- 让用户在一个界面中创建、验证、启用、停用和删除多个 Codex CLI 档案。
- 在不解析 Codex 私有数据库、不读取未公开状态文件的前提下，聚合已注册档案的本机任务。
- 将任务开始、等待审批、完成、失败、取消等事件安全地推送到已配置的机器人频道。
- 将敏感信息留在系统安全存储中，避免密钥、访问令牌、原始提示词与代码进入前端状态、普通日志、导出内容或机器人消息。

### 1.2 非目标

- 不提供 OpenAI/ChatGPT 账号注册、密码管理、账单管理、订阅管理或账号共享。
- 不直接切换 Codex 桌面端、IDE 扩展或其他客户端的登录态。
- 不提供 QQ、微信、机器人入站 Webhook、机器人命令、远程任务控制、任意 Shell 命令执行或任意提示词执行。
- 不读取或反向解析 `auth.json`、SQLite 数据库、日志文件等未公开本地状态，来补足任务列表或身份信息。
- 不提供云端中转、跨设备同步、多人协作、团队 RBAC 或集中审计。

## 2. 用户与核心场景

### 2.1 目标用户

个人开发者在同一台电脑上维护多个工作身份，例如个人 ChatGPT 身份、不同 API 项目身份，且希望在离开终端时仍能从常用群机器人收到任务结果。

### 2.2 用户故事

1. 作为开发者，我可以新建一个“工作账号”档案，完成 ChatGPT 浏览器登录或录入 API Key，并确认它可运行 Codex CLI。
2. 作为开发者，我可以为任务选择明确的档案；正在运行的任务始终保留其创建时的档案归属，不因界面切换而改变。
3. 作为开发者，我可以在任务中心看到已注册档案中可枚举的进行中任务与近期历史，并快速继续或取消任务。
4. 作为开发者，我可以将一个飞书、Telegram 或 Discord 频道绑定到指定事件，并先发送测试消息确认配置正确。
5. 作为开发者，我可以确认机器人只收到状态与简短摘要，而不会收到密钥、原始提示词、代码、命令输出或完整模型回复。

## 3. 产品范围与术语

| 术语            | 定义                                                                                     |
| --------------- | ---------------------------------------------------------------------------------------- |
| 档案（Profile） | 应用管理的本地 Codex 运行身份，包含显示元数据、配置层、安全凭据引用和独立运行目录。      |
| 配置档案        | Codex CLI 的 `--profile <name>` 配置覆盖层；它只用于配置，不等同于登录身份。             |
| 运行目录        | 某一应用档案启动 CLI/App Server 时使用的独立 `CODEX_HOME`。                              |
| 任务            | Codex App Server 中的线程及其当前或最近一次 turn 的可视化状态。                          |
| 频道（Channel） | 一个飞书机器人、Telegram 目标会话或 Discord Incoming Webhook 的通知目标。                |
| 可枚举          | 可由当前安装版本的 Codex App Server 通过公开协议返回；不可枚举数据不得通过文件扫描补取。 |

## 4. 功能需求

### 4.1 首次使用与环境检测

首次启动时显示四步引导：

1. 检测 `codex` CLI 是否已安装、可执行且版本满足 App Server 接入所需能力。
2. 创建并验证至少一个 Codex 档案。
3. 可选地创建一个机器人频道。
4. 可选地发送测试通知，并进入概览页。

引导允许跳过通知配置，但没有通过 CLI 与档案验证时不得启动任务。缺少 CLI、版本不支持、App Server 无法初始化、登录失效或系统安全存储不可用时，必须给出原因、恢复步骤和“重新检测”操作。

### 4.2 多账号档案

#### 4.2.1 档案模型

每个档案至少包含以下非敏感元数据：

| 字段                      | 要求                                                                     |
| ------------------------- | ------------------------------------------------------------------------ |
| `id`                      | 应用生成的稳定 UUID，不因显示名称修改而变化。                            |
| `name`                    | 用户可读名称；同一设备中唯一。                                           |
| `slug`                    | 仅含字母、数字、连字符与下划线，用于 CLI 配置档案名与本地目录名。        |
| `color` / `avatar`        | 仅用于视觉区分，不承载账号身份信息。                                     |
| `authType`                | `chatgpt` 或 `apiKey`。                                                  |
| `state`                   | `active`、`disabled`、`needsReauth`、`unavailable`。                     |
| `runtimeHome`             | 应用拥有的、仅用于此档案的 `CODEX_HOME` 路径；界面不显示其中的凭据内容。 |
| `createdAt` / `updatedAt` | 用于排序和审计展示。                                                     |

创建档案时，用户必须选择 ChatGPT 登录或 API Key：

- **ChatGPT 登录**：应用调用已安装 CLI 的标准登录流程，由用户在系统浏览器完成认证；应用不得采集账号密码、浏览器 Cookie 或 OAuth 回调内容。
- **API Key**：用户在原生安全输入控件中粘贴密钥；保存后仅显示不可逆掩码和最后更新时间，不再返回明文。

每个档案均使用独立运行目录与独立 CLI 配置层。CLI 配置使用 `codex --profile <slug>`，配置内容仅保存该档案相对默认值的覆盖项。用户选择不同档案启动任务时，应用必须同时选择对应运行目录与对应配置档案。

> Codex 的 `--profile` 是配置覆盖机制而非身份切换机制；身份隔离由独立运行目录和安全凭据处理共同保证。实现前必须在三端验证 ChatGPT 登录在该隔离模型下不会串用凭据；未通过验证的平台不得宣称支持多 ChatGPT 身份，只能启用已验证的 API Key 档案。

#### 4.2.2 安全凭据与隐私

- macOS 使用 Keychain，Windows 使用 Credential Manager，Linux 使用 Secret Service 兼容密钥环。
- 应用要求 Codex CLI 使用系统 keyring 存储凭据；不接受从文件型 `auth.json` 导入凭据，也不得在系统密钥环不可用时回退为明文文件保存。
- API Key、Codex 访问令牌、机器人 Webhook URL 中的密钥段、Telegram Bot Token 和 Chat ID 均是敏感值：不得写入 React 状态持久化、应用日志、崩溃报告、剪贴板、导出文件或通知记录。
- 删除档案必须二次确认。用户可选择“仅移除应用登记”或“移除登记并清除应用创建的本地运行目录与对应安全存储引用”；后者仅删除本应用明确拥有的档案资源，不触碰默认 `~/.codex`。
- 停用档案后，禁止新建任务与新通知投递；已运行任务保留可见状态，允许用户取消。

#### 4.2.3 桌面端兼容

- 提供“打开 Codex 桌面端”入口和兼容状态说明。
- 仅可同步用户明确选择的非凭据配置，例如模型、推理强度、审批策略和沙箱预设；同步前必须展示差异并允许取消。
- 不写入桌面端认证缓存、不调用未公开登录接口、不承诺桌面端任务必然可枚举。
- 任何无法由公开 App Server 返回的桌面端任务均显示为“当前 Codex 版本不可枚举”，不得尝试扫描其本地数据库或日志。

### 4.3 本机任务中心

#### 4.3.1 数据来源与边界

每个已启用档案启动一个本机 Codex App Server 子进程，并使用默认的 stdio JSONL 传输。应用在连接后完成初始化，使用公开线程与 turn 接口获取可枚举会话、开始/恢复/中断任务，并消费流式事件。

- 不监听公网端口；不使用非本机 WebSocket 监听。
- 不依赖实验性 API 字段或方法作为 MVP 的必要功能。
- 任务中心仅聚合当前设备、已注册档案、当前 CLI/App Server 版本可返回的任务。
- 应用保存的是最小化任务索引，而非 Codex 完整历史：档案 ID、线程 ID、来源、仓库显示名、状态、时间、耗时、短摘要、脱敏错误码和投递关联。原始提示词、完整 agent 回复、工具调用参数、命令输出和文件 diff 不得复制到应用索引。
- 本地任务索引和投递记录保留 30 天；每天清理过期记录。Codex 自身的历史保留策略由 Codex 管理，本应用不修改它。

#### 4.3.2 任务状态与操作

| 展示状态          | 来源/条件              | 可用操作                      |
| ----------------- | ---------------------- | ----------------------------- |
| `running`         | turn 已开始且未完成    | 查看状态、继续引导、取消      |
| `waitingApproval` | 收到需要用户审批的事件 | 打开本机 Codex 处理审批、取消 |
| `completed`       | turn 正常完成          | 查看摘要、继续                |
| `failed`          | turn 以错误结束        | 查看脱敏原因、继续            |
| `cancelled`       | 用户或运行时中断       | 继续                          |
| `unavailable`     | 当前版本或来源无法枚举 | 查看原因、重新检测            |

任务中心必须支持：

- 新建任务：用户选择档案、工作目录和任务描述后创建线程与 turn。创建前显示将使用的档案、目录和权限预设。
- 继续任务：以原档案和原线程继续，不能将一个既有线程迁移到另一个档案。
- 取消任务：要求二次确认，并调用公开的 turn 中断能力。
- 查询与筛选：按档案、状态、仓库、关键词、开始时间筛选；关键词只匹配已保存的最小化元数据和短摘要。
- 刷新：重新从所有已启用档案的 App Server 获取状态；任一档案失败不能阻塞其他档案结果。

### 4.4 机器人通知

#### 4.4.1 支持的频道

| 平台     | 所需配置                 | MVP 能力                              |
| -------- | ------------------------ | ------------------------------------- |
| 飞书     | 自定义机器人 Webhook URL | 发送文本/卡片状态通知与测试消息。     |
| Telegram | Bot Token、Chat ID       | 调用 Bot API 发送状态通知与测试消息。 |
| Discord  | Incoming Webhook URL     | 发送状态通知与测试消息。              |

一个档案可关联多个频道；一个频道也可订阅多个档案。创建频道时必须验证必填项的格式，但不显示完整敏感值。用户保存后必须可以发送测试消息；测试成功前频道状态为 `unverified`，不能自动订阅任务事件。

#### 4.4.2 事件、内容与投递

可订阅事件固定为：任务开始、等待审批、任务完成、任务失败、任务取消。每个频道默认订阅全部五类事件，用户可逐项关闭。

默认消息包含：

- 档案显示名称；
- 仓库显示名称或“未指定仓库”；
- 用户确认的任务标题；
- 当前状态与开始/结束时间；
- 已耗时；
- 最多 200 个字符的短摘要或脱敏失败原因。

默认消息不得包含原始提示词、代码、文件内容、命令输出、完整 agent 回复、绝对本机路径、API Key、访问令牌、Bot Token、Webhook URL 或 Chat ID。摘要在发送前必须经过敏感模式检测和截断；检测失败时仅发送状态，不发送摘要。

投递策略：立即尝试一次；失败后在 1 分钟和 5 分钟各重试一次。全部失败后记录为 `failed`，保留 HTTP 状态、平台错误类别与下一步建议，但不得保存请求头、请求体中的敏感字段或完整响应内容。投递记录保留 30 天。

MVP 只允许应用向外发送消息：不创建 Webhook 接收服务、不开放入站路由、不暴露公网端口，也不接受机器人对任务的控制命令。

## 5. 界面与交互要求

主导航固定为以下四个入口：

1. **概览**：CLI/App Server 健康状态、进行中任务、等待审批任务、最近投递失败和快速操作。
2. **账号**：档案卡片、登录/验证、启用/停用、配置差异、删除与桌面端兼容提示。
3. **任务**：任务列表、筛选、详情、新建、继续、取消与刷新。
4. **通知**：频道列表、订阅规则、测试消息、投递记录和失败重试状态。

界面必须优先呈现状态而非配置细节：所有敏感字段使用掩码；验证、测试、取消、删除等有外部效果的操作必须显示明确结果和可恢复建议。空状态要分别说明“尚未创建档案”“档案不可用”“当前无任务”“尚未配置频道”。

## 6. 组件边界与数据流

| 组件              | 输入                                       | 输出/职责                                                     |
| ----------------- | ------------------------------------------ | ------------------------------------------------------------- |
| `ProfileStore`    | 档案元数据、配置变更、安全存储引用         | 档案生命周期、隔离运行目录、敏感值掩码。                      |
| `CodexRuntime`    | `Profile`、任务操作                        | CLI 健康检查、App Server 生命周期、线程/turn 操作、流式事件。 |
| `TaskRepository`  | 公开任务快照与事件                         | 跨档案最小化索引、30 天清理、筛选与状态归一化。               |
| `NotifierAdapter` | 脱敏后的 `NotificationEvent`、频道安全引用 | 平台配置验证、消息渲染、测试发送、重试和投递结果。            |

核心数据流如下：

1. 用户选择档案并创建或继续任务。
2. `CodexRuntime` 以该档案的隔离运行目录启动本机 App Server，并接收公开的任务事件。
3. `TaskRepository` 将事件归一化为最小化任务快照，更新界面。
4. 命中的频道订阅生成 `NotificationEvent`；脱敏后交给对应 `NotifierAdapter` 投递。
5. 投递结果写入最小化投递记录，概览页仅显示状态和可操作的失败说明。

所有网络请求由 Rust 侧的受限通知模块发起；前端不得直接持有频道密钥或调用机器人 API。实现时必须为所需网络域名设置最小 Tauri capability 与 CSP 范围。

## 7. 安全、兼容与错误处理

### 7.1 强制安全要求

- 不使用 `danger-full-access` 作为默认任务权限；创建任务时明确显示档案所选权限预设。
- 不将密钥传入 URL、命令行参数、常规环境日志或前端持久化存储。
- App Server 仅采用 stdio 本地连接；禁止将其直接暴露到局域网或公网。
- 外发通知只访问用户显式配置的平台端点；禁止通配网络访问与未经确认的重定向。
- 所有删除、取消、停用和桌面端配置同步均要求确认；失败不得导致默认 `CODEX_HOME` 或其他档案被修改。

### 7.2 降级规则

| 情况                              | 必须行为                                                 |
| --------------------------------- | -------------------------------------------------------- |
| CLI 未安装或版本过低              | 不启动任务；显示安装/升级说明和重新检测按钮。            |
| App Server 不能初始化或协议不兼容 | 将档案标为 `unavailable`；保留历史索引但停止刷新与通知。 |
| ChatGPT 登录过期                  | 标为 `needsReauth`；禁止新任务，保留历史与通知记录。     |
| 系统密钥环不可用                  | 禁止新增或更新任何凭据，绝不回退为明文文件。             |
| 单个档案运行时故障                | 隔离该档案错误，其他档案仍可刷新与运行。                 |
| 单个频道投递失败                  | 不影响任务执行；按既定策略重试并显示投递失败。           |
| 无法枚举的任务                    | 标注 `unavailable` 并解释来源限制；不扫描私有状态文件。  |

## 8. 验收标准与测试场景

### 8.1 档案与安全存储

- 在 macOS、Windows、Linux 上分别验证可用的系统密钥环；敏感值不能从 UI、应用日志、导出内容或投递记录恢复。
- 同一档案可完成 ChatGPT 登录或 API Key 验证；停用、重新认证和删除后的状态正确。
- 验证多个 ChatGPT 档案在每个平台是否真正隔离。任一平台无法证明隔离时，必须禁用该平台的多 ChatGPT 档案入口并提示只支持已验证模式。
- 验证档案 A 启动的任务不会因用户选择档案 B 而改变身份、配置或通知归属。

### 8.2 任务中心

- 验证 CLI 缺失、CLI 版本不支持、App Server 初始化失败、登录失效、任务中断和 30 天历史过期的 UI 与降级行为。
- 验证跨档案聚合、按档案/状态/仓库/关键词筛选、新建、继续、取消、刷新和状态映射一致。
- 验证不可枚举的任务不会触发对 `auth.json`、数据库、日志或其他私有文件的扫描。
- 验证应用索引不保存原始提示词、完整回复、代码、命令输出或文件 diff。

### 8.3 通知

- 飞书、Telegram、Discord 各自覆盖：配置格式校验、掩码显示、测试消息、五类任务事件、停用频道和订阅筛选。
- 覆盖超时、认证失败、限流和服务端错误；确认只会在立即、1 分钟、5 分钟共三次尝试后标记失败。
- 对包含 API Key、访问令牌、Webhook URL、绝对路径、代码片段和长文本的事件运行脱敏测试；不安全摘要必须退化为仅状态通知。

### 8.4 桌面端兼容

- 验证“打开 Codex 桌面端”不修改其登录状态。
- 验证非凭据配置同步前会展示差异，取消操作不会写入任何配置。
- 验证桌面端任务未被公开接口枚举时，产品明确显示限制且不进行私有数据访问。

## 9. 实施前置验证与发布门槛

在进入功能开发前，必须完成以下技术验证：

1. 对三端当前支持的 Codex CLI 版本，验证独立 `CODEX_HOME` 与系统 keyring 的组合能否可靠隔离多个 ChatGPT 登录身份。
2. 验证公开 App Server 的稳定接口可以列出目标范围内的本机线程、恢复线程、发起 turn、接收状态事件并中断 turn；不依赖实验性接口。
3. 验证三端 Tauri 安全存储、进程启动和最小网络 capability 能满足档案与三类通知频道需求。
4. 只有上述验证通过的平台和能力可以进入 MVP 发布矩阵；未通过的功能必须在 UI 中隐藏或标记为不可用，不能以文件扫描或弱化安全策略替代。
